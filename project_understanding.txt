4. Your Medallion Architecture

This is one of the most important things you should be able to explain in an interview.

Bronze

Bronze is your raw ingestion layer.

Its purpose is not to make the data beautiful.

Its purpose is:

Preserve what came from the source while adding ingestion metadata.

For example, your meter-reading structure includes fields such as:

LCLid
stdorToU
DateTime
kwh_hh
load_ts
source_system
schema_drift_detected
schema_drift_columns

So conceptually:

Source
   ↓
Bronze

The Bronze layer gives you:

traceability
replay capability
source preservation
ingestion timestamps
schema-drift information

10. Why run_as is important

This is something you've specifically worked through.

Your job should not execute as your personal user in QA/PROD.

Instead:

          │
          │ deploys job
          ▼

          │
          │ run_as
          ▼
Service Principal

You have separate service principals:

Energy Smart Meter DEV

This is a good enterprise pattern.

The deployment identity needs the equivalent servicePrincipal.user / Use permission to bind the service principal to the job. That's exactly the permission issue we previously encountered.

15. Your DBCR safety mechanism

This is another good engineering feature.

Before Liquibase actually modifies the database:

liquibase updateSQL
       ↓
     plan.sql
       ↓
 DBCR guard
       ↓
Liquibase update

Your guard checks for dangerous operations.

You've specifically designed it to protect against operations such as:

DROP
DELETE
TRUNCATE
CREATE SCHEMA
CREATE CATALOG

The idea is:

Generate the SQL first, inspect it automatically, and only then apply it.

That is a strong CI/CD safety pattern.

25. The authentication issue we fixed

You had an issue where CI tried to find:

/home/runner/.databrickscfg

because the bundle configuration was referring to:

profile: energy-dev

That profile existed on your local machine, but GitHub Actions doesn't have your local .databrickscfg.

We changed the architecture so CI uses environment authentication:

DATABRICKS_HOST
DATABRICKS_TOKEN
DATABRICKS_AUTH_TYPE=pat

instead of relying on your personal local profile.

After that:

databricks bundle validate -t qa

worked.

28. The most important architecture distinction

If you need to explain this project in an interview, don't describe it as:

"I created some Databricks notebooks to process smart meter data."

That's underselling it.

Explain it as:

"I built an environment-aware Databricks lakehouse platform for smart-meter data, using a Medallion architecture with Bronze, Silver and Gold layers. Data is processed using PySpark and governed through Unity Catalog. Database schema changes are managed separately using Liquibase, with a DBCR safety gate before execution. Databricks resources are packaged using Databricks Asset Bundles, while GitHub Actions provides CI/CD across DEV, QA and PROD. Production jobs use environment-specific service principals through run_as, while deployment authentication is handled independently through CI credentials."

That's a 5+ year Data Engineer-level explanation.
